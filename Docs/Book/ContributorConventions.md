# RDKit contributor conventions

Condensed from 737 review and discussion entries on 223 other authors’ PRs, collected September 15, 2026. These are review-derived conventions and examples, not an official style guide; the collection includes historical comments on recently updated PRs.

## 1. Chemistry and architecture

- **Separate file-format interpretation from general chemistry behavior.** Resolve format-specific query handling in the parser when possible; change shared sanitization only when the chemistry rule itself warrants it. Preserve the semantics of existing operations: replacing default sanitization’s symmetrized rings with `findSSSR()` changes behavior. [Parser boundary](https://github.com/rdkit/rdkit/pull/9178#issuecomment-4088450085), [ring semantics](https://github.com/rdkit/rdkit/pull/9536#discussion_r3979008059).
- **Respect the molecular model.** Existing algorithms assume one bond per atom pair; richer monomer connectivity should fit that representation. Keep `ROMol` in interfaces where it signals unchanged connectivity. [Graph invariant](https://github.com/rdkit/rdkit/pull/9373#discussion_r3506458691), [ROMol intent](https://github.com/rdkit/rdkit/pull/9536#issuecomment-5480548694).
- **Avoid depending on legacy stereo side effects.** Non-legacy stereochemistry perception does not populate `_CIPCode`; let `assignStereochemistry(cleanIt=true)` perform its existing cleanup. [Stereo review](https://github.com/rdkit/rdkit/pull/9130#discussion_r3049213356).
- **Build on existing chemistry implementations.** Reuse RDKit descriptors; supply literature references, meaningful correctness tests, and justification before adding another numerical dependency where Eigen may suffice. [Descriptor review](https://github.com/rdkit/rdkit/pull/9099#pullrequestreview-3824014797).

## 2. Public APIs and bindings

- **Preserve the meaning of existing C++ and Python code.** Every public API carries a compatibility obligation, even if it seems rarely used. Breaking signatures or behavior needs a clear justification and notification in `ReleaseNotes.md` → `Backwards incompatible changes`. Consider deprecated forwarding functions when renaming APIs. Preserve positional Python calls: changing the meaning of `GetProp('bar', True)` was specifically rejected. [Release notes](https://github.com/rdkit/rdkit/pull/9478#pullrequestreview-4906991727), [forwarding](https://github.com/rdkit/rdkit/pull/9204#discussion_r3131504364), [Python compatibility](https://github.com/rdkit/rdkit/pull/9346#issuecomment-4715006026).
- **Update both Python bindings.** Keep `Wrap` and `nbWrap` signatures aligned; both use the Python tests in `Wrap` to maintain API compatibility. [Binding convention](https://github.com/rdkit/rdkit/pull/9483#discussion_r3758736488).
- **Choose the installed API deliberately.** `rdkit_headers()` installs headers for clients; keep test-only helpers out. Export symbols where DLL builds need them—exporting a symbol does not itself require shipping its header. [Installed headers](https://github.com/rdkit/rdkit/pull/9228#pullrequestreview-4151978038), [export distinction](https://github.com/rdkit/rdkit/pull/9331#discussion_r3397108744).

## 3. Implementation idioms

The preferences below include older, still-callable patterns worth avoiding in new code; they are not a list of formal deprecations.

- **C++: use RDKit’s error vocabulary.** Use `ValueError` for invalid user input, `PRECONDITION` for programming-contract violations, and `CHECK_INVARIANT`/`POSTCONDITION` for internal/result checks. Report diagnostics through `BOOST_LOG`; avoid generating SMILES just to log an error. [Input errors](https://github.com/rdkit/rdkit/pull/9430#pullrequestreview-4783571067), [contracts](https://github.com/rdkit/rdkit/pull/9337#discussion_r3412099244), [logging](https://github.com/rdkit/rdkit/pull/9099#discussion_r2827788297).
- **C++: prefer molecule ranges over explicit iterator pairs.** Use `mol.atoms()`, `mol.bonds()`, and `mol.atomBonds(atom)` instead of begin/end loops or `boost::make_iterator_range(mol.getAtomBonds(atom))`. [Atom/bond modernization](https://github.com/rdkit/rdkit/pull/9243), [bond traversal](https://github.com/rdkit/rdkit/pull/8450). For repeated removals, consider `beginBatchEdit()` / `commitBatchEdit()`; when only neighboring atoms are needed, use `mol.atomNeighbors(...)`. [Batch editing](https://github.com/rdkit/rdkit/pull/9444#discussion_r3736228210), [neighbors](https://github.com/rdkit/rdkit/pull/9485#discussion_r3850340953).
- **C++: prefer smart-pointer-returning v2 parsers.** For example, use `v2::FileParsers::MolFromMolFile(...)` instead of the raw-pointer-returning `MolFileToMol(...)` and manual deletion. Greg’s ShapeHelpers modernization demonstrates this migration. [Parser modernization](https://github.com/rdkit/rdkit/pull/8954).
- **C++: prefer parameter-object overloads where available.** Use `SmilesWriteParams` with named settings over long positional argument lists; similarly, prefer the `setTopolBounds()` overload taking `EmbedParameters` over its positional boolean options. [Bounds parameters](https://github.com/rdkit/rdkit/pull/9412). For enum/string conversions, follow `BETTER_ENUM` examples in `RGroupDecompParams.h`. [Parameters](https://github.com/rdkit/rdkit/pull/9396#discussion_r3576027419), [enums](https://github.com/rdkit/rdkit/pull/9373#discussion_r3506543854).

## 4. Regression tests

- **Test the implementation and its Python interface.** As a working rule, test C++ features in C++ and Python features in Python. For C++ functionality exposed to Python, add a Python test as well to exercise the wrapper; the shared `Wrap` tests cover both binding implementations. This combines Greg’s requests for a C++ reproducer and for Python coverage. [C++ reproducer](https://github.com/rdkit/rdkit/pull/9190#discussion_r3911190325), [Python test](https://github.com/rdkit/rdkit/pull/9322#discussion_r3813354092), [shared wrapper tests](https://github.com/rdkit/rdkit/pull/9483#discussion_r3758736488).
- **Make tests visible to CTest.** Use Catch2 assertions in C++; printing failures is insufficient. For Python, `add_pytest()` invokes a script directly, while `add_pythonpytest()` uses directory discovery—verify the new tests actually execute. [C++](https://github.com/rdkit/rdkit/pull/9322#discussion_r3813278646), [Python](https://github.com/rdkit/rdkit/pull/9242#discussion_r3188058964).
- **Use RDKit’s current test idioms.** Include the GitHub issue number in regression names and use Catch2 `WithinAbs` rather than old `feq()` checks. [Names](https://github.com/rdkit/rdkit/pull/9405#discussion_r3627379703), [tolerances](https://github.com/rdkit/rdkit/pull/9471#discussion_r3932511281).
- **Control molecular fixtures.** Add Hs before embedding unless testing their absence deliberately. For force-field tests, supply coordinates via molblock/CXSMILES where possible to avoid introducing a `DGeomHelpers` dependency; preserve Hs when parsing. [Embedding](https://github.com/rdkit/rdkit/pull/9460#discussion_r3736787530), [coordinates](https://github.com/rdkit/rdkit/pull/9228#discussion_r3121493404).

## 5. Source style

- **Use camelCase for variables, including Python.** Preserve leading underscores marking private names. Greg explicitly favors Python docstrings and editor stubs over adding inline type annotations. [Naming](https://github.com/rdkit/rdkit/pull/9277#discussion_r3220110150), [privacy](https://github.com/rdkit/rdkit/pull/9277#discussion_r3220106370), [annotations](https://github.com/rdkit/rdkit/pull/9277#issuecomment-4427219936).
- **Apply the project formatters.** Use `clang-format` for C++, `yapf` for Python, and braces even for single-statement C++ branches and loops. [C++](https://github.com/rdkit/rdkit/pull/9216#pullrequestreview-4387041777), [Python](https://github.com/rdkit/rdkit/pull/9277#pullrequestreview-4278336651), [braces](https://github.com/rdkit/rdkit/pull/9485#pullrequestreview-4983341452).
